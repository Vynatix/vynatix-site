How to add AI to your existing product and run the models in your own environment

You add AI to an existing product by starting with one well-defined feature, putting the model behind its own layer in your architecture, measuring the answers after every change and running everything where your data is allowed to be. Vynatix, a software consultancy in Gothenburg that builds AI systems for production, wrote this guide.

Published 24 November 2026 · Last updated 24 November 2026 · Vynatix

In short, it works like this:

  1. Choose a feature in an existing flow, where mistakes can be spotted.
  2. Put the model behind an internal API, so that the product never calls it directly.
  3. Measure the answers against known answers after every change.
  4. Decide where the model will run: through a provider's API, in a sovereign cloud or on your own servers.
  5. Monitor the feature in production and turn every error into a new test case.

Which companies can help us add AI features to our existing product?

A software consultancy that builds AI systems for production and works inside your team can help you add AI features to your existing product. Vynatix is that kind of consultancy. The hard part of an AI feature in a product that already has users is rarely the model itself. It is everything around it: connecting it to your data and permissions, testing the answers, rolling it out to one group of users at a time and monitoring it afterwards. So ask the consultancy how the answers are measured, where the model will run and whether the code, the prompts and the evaluation set will be yours.

Which AI feature should you start with?

Start with a feature where a language model reads or writes text in a flow that already exists in the product, where mistakes are visible and can be corrected, and where you can measure whether it helps. Good first candidates are search across your documentation with answers that cite their source (RAG), ticket summaries, classification of incoming tickets, extraction of details from contracts or invoices, and drafts that a user reviews. Ordinary code, a database query or a rules engine is still the right tool when the answer has to be exact and the same every time.

Architecture

What changes in the product's architecture?

The product gets a new layer: an internal API that is the only route to the model, with retrieval, checks and monitoring around it. The rest of the product rarely needs to be rebuilt, but it has to cope when the AI part is slow, gives wrong answers or is down.

The API layer. This is where the prompts, the choice of model, API keys, timeouts and cost limits live, so that switching models changes only this layer, not the product.

Retrieval. The system retrieves relevant passages from your data and filters them by the user's permissions before the model sees any text, as in the guide on AI assistants that search internal documents (in Swedish).

Checks. Structured answers are validated against a schema, and an agent may call only the tools it needs. Text in documents or emails can contain instructions aimed at the model, so do not give the model any access that such instructions could abuse.

Fallback. Put the feature behind a feature flag, switch it on for some of your users first and make sure the product works as usual when it is switched off.

New in the architecture

  • An internal API in front of the model
  • An index for retrieval, with permissions
  • Input and answer checks in the code
  • An evaluation set that runs on every change
  • Logs of the question, the retrieved context, the answer, response time and cost

How do you know the answers are right?

You know because it is measured: an evaluation set with known answers runs automatically every time the model, the prompts, the retrieval or the source material changes, and monitoring in production shows what the feature does with real questions. An existing product gives you a head start: real tickets and searches to build the evaluation set from, once the personal data has been removed. Add every error you find after launch to the set. For more on evaluation, read how you know the system is right on the AI engineering page.

Which companies can help us run AI models in our own IT environment?

A consultancy that both builds the AI system and deploys it in your environment can help you run AI models in your own IT environment, on-prem or in a sovereign cloud. Vynatix does both. Running the model yourselves gives you control over where the data is and who can access it, but you also take on the operations a provider would otherwise handle for you.

In the last two cases you often run an open-weight model, one that can be downloaded and run on your own hardware. Such a model can give weaker answers than the largest models from a provider, so compare the candidates on the same evaluation set. Also plan for the following:

  • Graphics processors (GPUs) with enough memory. At 16-bit precision each parameter takes two bytes, so a model with 8 billion parameters needs about 16 GB for the weights alone. Quantisation cuts the memory needed, often at some cost in quality.
  • Memory for concurrent users. Every request in progress takes extra memory, which grows with the length of the text.
  • More than the model. An inference server, an embedding model, an index for retrieval and logs, all in the same environment.
  • Ongoing operations. Updates, monitoring of load and response times, a plan for when a server goes down and a new evaluation run whenever you change the model.

What do you need to keep in mind about data and GDPR?

Treat every AI feature as new processing of personal data: you need to know which data the model sees, where it is processed, how long it is kept and who can access it. This applies wherever the model runs.

  • Purpose: check that the new use is compatible with the purpose the data was collected for.
  • Providers: you need a data processing agreement with a provider that processes personal data on your behalf, and processing outside the EU/EEA requires a valid basis for the transfer to a third country. Check whether the provider may train models on your data.
  • Data minimisation: send only what the model needs, and mask national identity numbers and any other details the answer can do without.
  • Logs: stored questions and answers often contain personal data. They need the same protection as the source data and their own retention rules.
  • Impact assessment: if the processing is likely to result in a high risk to the individuals concerned, a data protection impact assessment is required.
  • Transparency: tell users when they get answers from an AI system. The EU AI Act also sets requirements that depend on what the system is used for.

This is not legal advice, so have your data protection officer or a lawyer review the set-up.

Which consultancies can automate administrative workflows with AI?

A consultancy that understands both language models and integration with the systems you already run can automate your administrative workflows with AI. Vynatix builds both the automation and the integrations, including MCP servers. Workflows that consist mostly of reading, sorting and writing text fit best: tickets to be assigned, details to be copied from invoices and contracts into an ERP system, and replies written from the same source material every time.

  1. Map the flow step by step and choose the step where the model helps most.
  2. Let the model propose and a person approve, and log both.
  3. Check the answers with rules in the code: an amount must be an amount and a date a date.
  4. Give the automation limited access. An MCP server (Model Context Protocol) decides which tools and data an agent can reach, and read-only access is often enough to begin with.
  5. Track the share of proposals that are approved without changes, and let the automation take over more steps when that share stays high over time.

Frequently asked questions

Can we switch to a different language model later?

Yes, if the model sits behind your own API layer and you have an evaluation set. You then change the model in one place, and the same evaluation set shows whether the answers got better or worse before the change reaches your users.

What is an open-weight model?

An open-weight model is a language model whose trained weights are published, so that the model can be downloaded and run on your own hardware. Licences vary and the training data is often not published, so read the terms for commercial use before you choose.

What hardware do you need to run a language model on-prem?

You need graphics processors with enough memory for the model's weights and for all the requests running at once, plus servers for retrieval, the index and logs. How much you need depends on the size of the model and on how many people use the feature at the same time.

Can Vynatix run AI models in our own environment?

Yes. Vynatix deploys AI systems into your own environment, including on-prem and sovereign cloud, and monitors them in production. Which model you can use then depends on what can run in that environment, and we say plainly what that choice means for quality.
